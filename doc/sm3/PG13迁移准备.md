# PostgreSQL 13 → 17.10 SM3：先迁移普通数据

按最新要求，本次不迁移用户安装的扩展及外部表。继续使用已发布的 `172.16.61.68:8080/library/postgres-sm3:17.10-sm3.3`，保留目标现有数据目录、postgres 的 SHA256 密码和 HBA；不需要为此更新数据库镜像。

源端为 docker-48 的 postgres-13 容器：38 个非模板数据库、9 个角色；60 张外部表分布在 10 个库中。6 个库安装了 redis_fdw。postgres 数据库也在迁移检查范围内。旧实例继续保留，本次是测试复制。

## 本次范围

- 迁移普通业务表的数据、序列，以及不依赖被排除对象的约束、索引、视图、函数和权限。
- 不恢复 redis_fdw、postgres_fdw、pg_stat_statements、hstore、pg_trgm、pgcrypto、btree_gin、tablefunc、unaccent 等额外扩展，也不恢复外部服务器、用户映射、外部表。
- 保留 PostgreSQL 默认自带的 plpgsql；它不属于本次额外安装的业务扩展。
- 与扩展或外部表有关的对象，先形成清单再决定如何排除。普通表如果有 hstore 等字段，不能直接跳过整张表或删除字段，也不能把“恢复报错后继续执行”当作迁移成功。

扩展文件已经包含在镜像中，与数据库是否执行 CREATE EXTENSION 是两回事。本次无需卸载镜像内已有的标准扩展文件。

## 先做依赖检查

把 [check-migration-dependencies.sh](../../deploy/sm3/check-migration-dependencies.sh) 放到 docker-48，执行：

```bash
bash check-migration-dependencies.sh > migration-dependencies.txt
```

脚本只读取 postgres-13 的系统目录，遍历 38 个非模板库，不查询外部服务，不改变数据库。它会列出受扩展或外部表影响的普通表字段、默认值、索引、约束、视图、函数等。可以提供检查结果；无需提供密码或角色备份 SQL。

输出类别说明：

- `TABLE_COLUMN_REQUIRES_DECISION`：普通表字段依赖扩展，需要先决定字段类型如何处理，不能漏掉数据后继续。
- `FOREIGN_TABLE_TO_EXCLUDE`：本次计划排除的外部表。
- `DEFINITION_DEPENDENCY`：需要逐项核查的默认值、索引、视图、函数等依赖对象。

脚本退出码为 0 只表示检查成功，不表示这些依赖已经处理，也不表示恢复演练通过。

系统目录不能识别所有动态 SQL 或函数体中的运行时依赖，因此空结果还需结合恢复演练和业务测试确认。

## 后续恢复原则

1. 先检查依赖清单。普通表字段若依赖扩展类型，需要明确处理方案；本次不会自动转换字段或漏掉这些数据。
2. 先保存完整逻辑备份作为回退依据，再制作本次恢复清单。完整备份可能包含用户映射凭据，文件应仅限操作用户读取；不要把完整 SQL、密码散列或映射选项贴到聊天中。
3. 对 custom 格式备份使用审核后的 pg_restore 清单，排除扩展、外部对象及受影响的对象；不要只过滤 CREATE EXTENSION，也不要忽略恢复错误。PG17 的 pg_dump 支持 --exclude-extension，但这个参数不会自动解决所有依赖。
4. 先恢复另外 8 个角色及必要的成员关系、设置，避免覆盖目标 postgres 的密码、属性和配置。旧密码散列不会因为默认 password_encryption=scram-sm3 就自动转换；业务账号按客户端能力重设密码和配置 HBA。
5. 37 个新业务库分别创建和恢复；如目标已有同名库，先核查。postgres 库单独恢复所需内容，不删除或重建它，并保留目标管理账号与健康检查。逐库备份是各库独立快照，业务持续写入时不保证跨库处于同一时间点。
6. 在隔离环境先演练结构恢复，再恢复数据并检查表数据、序列、约束、所有权、权限，执行 ANALYZE；最后用改版 JDBC 验证 SM3 业务连接，用 Navicat 验证 SHA256 管理连接。缺少扩展相关功能的业务，需要单独验收。

当前尚未导出或导入这 38 个实际数据库。依赖检查完成后，才能给出与实际清单匹配的过滤和恢复命令。不要将 PG13 数据目录挂载到 PG17，也不要删除原数据目录。

参考：[pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html)、[pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html)、[pg_dumpall](https://www.postgresql.org/docs/17/app-pg-dumpall.html)。
