# PostgreSQL 17.10 SM3 升级到 17.12

本仓库的 `17.12-sm3.3` 镜像以官方 PostgreSQL `REL_17_12` 为基线，重放现有
SCRAM-SM3 改造和容器部署修正。17.10 到 17.12 属于同一大版本的更新，官方说明不要求
`pg_upgrade` 或 dump/restore。升级前仍要保留可恢复的备份，并安排业务连接切换窗口。

## 升级前检查

先确认当前容器、数据卷和版本：

```bash
docker ps --filter name=postgres-sm3
docker inspect --format '{{.Config.Image}} {{range .Mounts}}{{.Name}}:{{.Destination}} {{end}}' postgres-sm3
docker exec --user postgres postgres-sm3 psql -X -d postgres -Atc \
  "SELECT version(); SHOW password_encryption;"
```

保存角色和数据库备份。生产环境还应保留一次可验证的物理备份或快照：

```bash
docker exec --user postgres postgres-sm3 pg_dumpall -g > globals-before-17.12.sql
docker exec --user postgres postgres-sm3 pg_dump -Fc -d postgres -f /tmp/postgres-before-17.12.dump
docker cp postgres-sm3:/tmp/postgres-before-17.12.dump ./postgres-before-17.12.dump
```

如果实例使用 `contrib/btree_gist`、`contrib/ltree` 或其他 C 扩展，按 17.11 和 17.12
发布说明检查相关索引，必要时在维护窗口执行 `REINDEX`。C 语言扩展应使用 17.12 的头文件
重新编译后再加载。

## 构建并发布 17.12 镜像

在本仓库的 `codex/sm3-17.12` 分支或对应发布提交上执行：

```bash
IMAGE=172.16.61.68:8080/library/postgres-sm3:17.12-sm3.3 \
  ./deploy/sm3/build-and-push.sh
```

脚本会构建并检查 `linux/amd64`，然后推送到镜像仓库。推送后记录镜像 digest：

```bash
docker image inspect --format '{{json .RepoDigests}}' \
  172.16.61.68:8080/library/postgres-sm3:17.12-sm3.3
```

## 使用原数据目录启动新容器

先停止旧容器，保留数据卷和宿主机目录。不要执行 `docker volume rm`，也不要删除
`/data/postgres-sm3`：

```bash
docker stop postgres-sm3
docker rm postgres-sm3
```

将启动脚本中的镜像改为 `17.12-sm3.3`，继续使用原来的数据目录挂载：

```bash
docker run -d --name postgres-sm3 \
  --restart unless-stopped \
  --platform linux/amd64 \
  -p 55432:5432 \
  -v /data/postgres-sm3:/var/lib/postgresql/data \
  172.16.61.68:8080/library/postgres-sm3:17.12-sm3.3
```

实际环境若使用 named volume、端口或环境文件，保留原来的值。已有 `PG_VERSION` 时入口
不会重新初始化，也不会修改已有角色密码、`pg_hba.conf` 或 `postgresql.conf`。

## 升级后验收

先看服务端版本和数据目录版本：

```bash
docker exec --user postgres postgres-sm3 psql -X -d postgres -c \
  "SELECT version();"
docker exec --user postgres postgres-sm3 cat /var/lib/postgresql/data/PG_VERSION
docker inspect --format '{{json .State.Health}}' postgres-sm3
```

确认业务账号仍能通过定制 JDBC 使用 `SCRAM-SM3`，管理员账号按现有 SHA256 HBA 规则连接，
再执行关键 SQL、写入、事务、备份和恢复抽样。健康检查应使用镜像内置的 `gosu postgres psql`
本地 socket 命令，不应再次出现 root 触发的 `Peer authentication failed`。

JDBC 仓库继续使用 `42.7.3-sm3.1`。PostgreSQL 17.12 的补丁版本更新不要求替换该驱动，
只有在 JDBC 源码自身需要修复或升级时才另行创建驱动版本。

如果验收失败，先停止 17.12 容器并保留现场日志，再用原 17.10-sm3.3 镜像挂载同一数据目录
回退。回退前不要继续写入新业务数据，并保留失败期间的日志和备份。

参考官方 [17.12 发布说明](https://www.postgresql.org/docs/17/release-17-12.html) 和
[17.11 迁移说明](https://www.postgresql.org/docs/17/release-17-11.html)。
