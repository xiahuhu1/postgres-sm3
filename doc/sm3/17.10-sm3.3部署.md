# 17.10-sm3.3：postgres 管理账号使用 SHA256，业务账号使用 SM3

本说明对应现有测试实例：容器 `postgres-sm3`，宿主机 `10.0.0.67:55432`，
数据目录 `/data/postgres-sm3`，Navicat 客户端 `192.168.110.28`。
`postgres` 继续作为管理员，不创建 `navicat_admin`。本说明替代旧文档中创建独立管理账号、
在启动脚本覆盖健康检查的操作；无需下载数据库源码包或更改 JDBC。

## 1. 更新镜像并重建容器

```bash
docker pull 172.16.61.68:8080/library/postgres-sm3:17.10-sm3.3
vi /opt/postgres-sm3/startup.sh
```

只将原启动脚本最后的镜像改为 `172.16.61.68:8080/library/postgres-sm3:17.10-sm3.3`，
保留原密码参数和 `/data/postgres-sm3:/var/lib/postgresql/data` 挂载，再执行：

```bash
bash /opt/postgres-sm3/startup.sh
```

这是同版本镜像更新，不涉及数据迁移。已有数据目录会继续使用；不要删除目录来重新初始化。
镜像更新本身不会改变已有账号密码或 HBA 规则。

## 2. 将 postgres 的密码格式改为 SHA256

```bash
docker exec -it --user postgres postgres-sm3 psql -X -d postgres \
  -f /usr/local/share/postgresql/set-postgres-sha256.sql
```

按提示输入两遍准备给 Navicat 使用的密码，可以沿用原密码。
脚本只在本次事务内选择 `scram-sha-256` 并重设 `postgres` 密码；实例默认值仍是 `scram-sm3`。
以后修改 postgres 密码，也使用这条命令；直接按实例默认值重设会变回 SM3。
业务 JDBC 必须使用独立业务账号，该账号的 SM3 密码不受本次操作影响。

## 3. 给管理连接添加 SHA256 规则

在宿主机备份并编辑实际挂载的配置：

```bash
cp -p /data/postgres-sm3/pg_hba.conf "/data/postgres-sm3/pg_hba.conf.bak.$(date +%Y%m%d%H%M%S)"
vi /data/postgres-sm3/pg_hba.conf
```

在现有远程 SM3 通配规则之前加入这一行，保留本地 `peer` 规则：

```conf
host all postgres 192.168.110.28/32 scram-sha-256
host all all      0.0.0.0/0        scram-sm3
```

第二行是已有规则，不必重复添加。HBA 使用第一条匹配规则，认证失败不会继续匹配。
先检查配置，输出应为零行；如有错误，修正后再执行重载：

```bash
docker exec --user postgres postgres-sm3 psql -X -d postgres -c \
  'SELECT line_number, error FROM pg_hba_file_rules WHERE error IS NOT NULL;'
docker exec --user postgres postgres-sm3 psql -X -d postgres -c 'SELECT pg_reload_conf();'
```

检查重载日志是否有配置错误。若存在地址转换，应按服务端实际看到的来源地址调整该 `/32` 规则。

## 4. 验证两种连接和健康检查

在 Navicat 重新连接 `10.0.0.67:55432`，账号 `postgres`，密码为第 2 步输入值，执行：

```sql
SELECT current_user, system_user;
```

应返回 `postgres`、`scram-sha-256:postgres`。
业务应用用定制 JDBC 和自己的 SM3 账号建立新连接，同一 SQL 应返回 `scram-sm3:业务账号名`。
两种连接分别用错误密码测试，均应拒绝；已有连接不能证明新密码和 HBA 已生效。

```bash
docker exec -i --user postgres postgres-sm3 psql -X -d postgres <<'SQL'
SHOW password_encryption;
SELECT rolname, rolpassword LIKE 'SCRAM-SHA-256$%' AS stored_as_sha256
FROM pg_authid WHERE rolname = 'postgres';
SQL
docker inspect --format '{{json .State.Health}}' postgres-sm3
docker logs --since 2m postgres-sm3
```

默认格式应为 `scram-sm3`，`stored_as_sha256` 应为 `t`。
新镜像内置健康检查以操作系统 `postgres` 身份通过本地 socket 执行 `SELECT 1`，
修复旧检查以 root 连接数据库 postgres 导致的 `Peer authentication failed`；无需额外启动参数。
等待健康检查完成，应为 `healthy`，日志不应再每十秒出现该 peer 错误。

全新空目录仍先初始化为 SM3，需要执行以上一次性管理账号配置；入口自动创建 `postgres`，不要再次 `CREATE ROLE postgres`。
全新空目录必须提供 `POSTGRES_PASSWORD` 或非空的 `POSTGRES_PASSWORD_FILE`，两者不能同时省略。
已有有效 `PGDATA` 时可以省略这两个参数，入口保留原 postgres 角色和密码；修改环境变量不会重置已有密码。
当前入口忽略 `POSTGRES_USER`，不会据此创建账号或选择密码算法。
以后从另一台机器复制数据库时，需要另行选择备份恢复方案；角色和密码格式不会自动转换为 SM3。
正式环境还需限制 HBA 来源、配置并验证 TLS、验证实际业务与备份恢复；本地健康检查只证明数据库可执行 SQL。
